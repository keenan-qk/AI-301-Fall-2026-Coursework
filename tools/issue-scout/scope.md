## Where candidates come from

Candidates may come from public GitHub repositories
outside the course's Path Review repository.

Prioritize repositories involving Python, C++, or C#,
particularly projects related to simulation, embedded
systems, aerospace, developer tools, or game development.

Candidate issues should be open and accessible for
independent evaluation.

The scout must evaluate each candidate using rubric.md.
Search results and GitHub labels alone do not establish
whether an issue is suitable.

Repository contribution policies must be respected.
Issues from inactive, archived, or unsuitable repositories
may be discovered but must still pass the rubric before
being accepted.

**Path Review house rule.** Path Review is a classroom, and your
classmates are not strangers. Ignore the usual claim signals here: other
students' claim comments (and there may be several on one issue) do not
block an issue, and finding some on the issue you want is normal. Claim
anyway: course credit attaches to the pull request you open, not to
whether it merges, so a shared issue costs nobody anything. Everything
else in the rubric applies as written.
